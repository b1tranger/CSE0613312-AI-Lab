# Code Explanation: Tic Tac Toe — Two Versions

This document explains both Python implementations of 3×3 Tic-Tac-Toe:

| File | Mode | AI? |
|---|---|---|
| `tictactoe_minimax.py` | Human (X) vs AI (O) | ✅ Minimax + Alpha-Beta Pruning |
| `tictactoe_2player.py` | Human (X) vs Human (O) | ❌ No AI |

---

## Part 1 — Shared Concepts (Both Files)

Both programs are built on the same three foundational ideas.

### 1.1 Board Representation

The 3×3 grid is stored as a **flat Python list of 9 strings**:

```python
board = [" "] * 9
```

Each element is either `" "` (empty), `"X"`, or `"O"`. The index maps to a visual position like this:

```
Index:          Display:
 0 | 1 | 2       1 | 2 | 3
 3 | 4 | 5  →    4 | 5 | 6
 6 | 7 | 8       7 | 8 | 9
```

> [!NOTE]
> Indices are 0-based internally, but the player sees 1-based numbers (1–9). The conversion is:  `index = player_input - 1`

Using a flat list (not a 2D list) keeps the code simple — rows, columns, and diagonals are just fixed groups of indices.

---

### 1.2 `create_board()`

```python
def create_board():
    return [" "] * 9
```

Returns a brand-new empty board. Called once at the start of each round. Using a function (rather than a global variable) ensures each game gets a clean, independent board.

---

### 1.3 `print_board(board)`

```python
def print_board(board):
    def cell(i):
        return board[i] if board[i] != " " else str(i + 1)

    print(f" {cell(0)} | {cell(1)} | {cell(2)} ")
    print("---+---+---")
    print(f" {cell(3)} | {cell(4)} | {cell(5)} ")
    print("---+---+---")
    print(f" {cell(6)} | {cell(7)} | {cell(8)} ")
```

The inner `cell(i)` helper decides what to print:
- If the cell is taken → show the mark (`X` or `O`)
- If the cell is empty → show the position number as a hint to the player

This means the board **teaches players where to click** without a separate legend.

---

### 1.4 `get_available_moves(board)`

```python
def get_available_moves(board):
    return [i for i, v in enumerate(board) if v == " "]
```

A **list comprehension** that scans all 9 cells and returns the indices of empty ones. Used by:
- Input validation (only accept available positions)
- The minimax algorithm (to know which moves to explore)
- Draw detection (if the list is empty and no winner → draw)

---

### 1.5 `WIN_LINES` Constant

```python
WIN_LINES = [
    (0, 1, 2), (3, 4, 5), (6, 7, 8),   # 3 rows
    (0, 3, 6), (1, 4, 7), (2, 5, 8),   # 3 columns
    (0, 4, 8), (2, 4, 6),              # 2 diagonals
]
```

All **8 possible winning combinations** are stored as tuples of 3 indices. Storing them as a constant avoids repeating the same logic in multiple places (DRY principle).

---

### 1.6 `check_winner(board)`

```python
def check_winner(board):
    for a, b, c in WIN_LINES:
        if board[a] == board[b] == board[c] and board[a] != " ":
            return board[a]          # returns 'X' or 'O'
    if not get_available_moves(board):
        return "Draw"
    return None
```

Steps:
1. Loop through all 8 win lines
2. If all 3 cells in a line are the same non-empty symbol → that player wins
3. If no winner found and no moves left → Draw
4. Otherwise → game is still going (`None`)

This function is called **after every move** in the game loop.

## Part 2 — `tictactoe_2player.py` (Human vs Human)

### 2.1 How the Game Works — Overview

```
main()
 │
 ├─ Greet players, ask for names
 │
 └─ Loop (while playing):
     ├─ print_scores()
     ├─ play_round(names) ──────────────────────────────────┐
     │   │                                                  │
     │   ├─ create_board()                                  │
     │   └─ Loop (while no winner):                         │
     │       ├─ print_board()                               │
     │       ├─ get_player_move() → validated input         │
     │       ├─ place mark on board                         │
     │       └─ check_winner() → break if done              │
     │                                                      │
     └─ Update scores, ask to play again ──────────────────-┘
```

---

### 2.2 `get_player_move(board, player_name, symbol)`

```python
def get_player_move(board, player_name, symbol):
    available = [str(m + 1) for m in get_available_moves(board)]
    while True:
        raw = input(f"  {player_name} ({symbol}), choose a cell "
                    f"[{', '.join(available)}]: ").strip()
        if raw in available:
            return int(raw) - 1
        print(f"  ✗ '{raw}' is not valid. Please choose an available cell.")
```

- Builds a list of available cell numbers **as strings** for easy comparison
- Uses a `while True` loop — keeps asking until valid input is given
- Converts the 1-based player input to a 0-based index before returning

---

### 2.3 `play_round(names)` — Core Game Loop

```python
def play_round(names):
    board = create_board()
    players = {
        "X": {"name": names[0], "symbol": "X"},
        "O": {"name": names[1], "symbol": "O"},
    }
    turn_order = ["X", "O"]
    turn_index = 0

    while True:
        symbol = turn_order[turn_index % 2]   # alternates X → O → X → ...
        player = players[symbol]

        print_board(board)
        move = get_player_move(board, player["name"], symbol)
        board[move] = symbol

        result = check_winner(board)
        if result is not None:
            # announce result, return winner code
            return result

        turn_index += 1
```

**Key design decisions:**
- `turn_index % 2` elegantly alternates between 0 and 1, cycling X and O
- Player data is stored in a dictionary keyed by symbol — easy to look up the name for any symbol
- The function **returns the result** (`'X'`, `'O'`, or `'Draw'`) so the caller can update scores

---

### 2.4 Score Tracking in `main()`

```python
scores = {"X": 0, "O": 0, "Draw": 0}

result = play_round(names)
scores[result] += 1        # 'X', 'O', or 'Draw' — all valid dict keys
```

The score dictionary uses the same symbols returned by `check_winner` as keys, so updating is one clean line — no `if/elif` chain needed.

## Part 3 — `tictactoe_minimax.py` (Human vs AI)

This version replaces Player 2 with an **AI that uses the Minimax algorithm** to play perfectly.

### 3.1 What is Minimax?

Minimax is a **decision-making algorithm** used in two-player zero-sum games. It works by:

1. Looking ahead at **every possible future game state**
2. Assigning a **score** to every terminal (end) state
3. The AI picks the move that **maximises its own score** assuming the opponent always plays **optimally** (minimising the AI's score)

```
                    AI's Turn (Maximizing)
                    Board: _ _ _  _ _ _  _ _ _
                    /         |         \
            O at 0        O at 1     O at 2 ...
           /      \
    X at 1    X at 2
    /    \
 O at 3  O at 4
  ...     ...
  [terminal states: Win/Loss/Draw → assign scores]
```

The name "Minimax" comes from alternating between:
- **MAX** step — AI tries to pick the highest-scoring move
- **MIN** step — Human is assumed to pick the lowest-scoring move (worst for AI)

---

### 3.2 `is_terminal(board)`

```python
def is_terminal(board):
    return check_winner(board) is not None
```

A simple wrapper. Returns `True` when the game is over (win or draw). Used by `minimax()` as the **base case** to stop recursion.

---

### 3.3 `minimax(board, depth, is_maximizing, alpha, beta)` — Full Explanation

```python
def minimax(board, depth, is_maximizing, alpha=-math.inf, beta=math.inf):
```

**Parameters:**

| Parameter | Meaning |
|---|---|
| `board` | Current game state |
| `depth` | How many moves deep we are in the search tree |
| `is_maximizing` | `True` = AI's turn, `False` = Human's turn |
| `alpha` | Best score AI is guaranteed so far (starts at −∞) |
| `beta` | Best score Human is guaranteed so far (starts at +∞) |

**Score convention:**

```python
if winner == "O":   return 10 - depth   # AI wins — prefer faster wins
if winner == "X":   return depth - 10   # Human wins — prefer slower losses
if winner == "Draw": return 0
```

The `depth` adjustment is important:
- `10 - depth`: A win in 3 moves scores 7, a win in 5 moves scores 5 → AI prefers to win **quickly**
- `depth - 10`: A loss at depth 3 scores −7, at depth 5 scores −5 → AI prefers to lose **later** (giving opponent more chances to make mistakes)

**Maximizing branch (AI's turn):**

```python
if is_maximizing:
    best = -math.inf
    for move in moves:
        board[move] = "O"                              # try this move
        score = minimax(board, depth+1, False, alpha, beta)  # recurse
        board[move] = " "                              # undo the move
        best = max(best, score)
        alpha = max(alpha, best)
        if beta <= alpha:
            break                                      # Beta cut-off ✂
    return best
```

**Minimizing branch (Human's turn):**

```python
else:
    best = math.inf
    for move in moves:
        board[move] = "X"
        score = minimax(board, depth+1, True, alpha, beta)
        board[move] = " "
        best = min(best, score)
        beta = min(beta, best)
        if beta <= alpha:
            break                                      # Alpha cut-off ✂
    return best
```

> [!IMPORTANT]
> **The "undo" pattern** — `board[move] = " "` after the recursive call — is critical. The same board list is reused throughout the entire search. After exploring a branch, we restore the cell so the next branch starts from the correct state. This is called **backtracking**.

---

### 3.4 Alpha-Beta Pruning

Alpha-Beta Pruning is an **optimisation** that skips branches that can never influence the final decision.

```
alpha = best score AI has found so far (lower bound)
beta  = best score Human has found so far (upper bound)

If beta ≤ alpha at any point:
    The opponent already has a better option elsewhere.
    No need to explore further — PRUNE this branch.
```

**Example:**
```
AI is considering move A (score 7) and move B.
While exploring move B, Human finds a response scoring 3.
Since 3 < 7, Human would prefer this path.
But AI already has move A scoring 7 → AI will never pick B.
Stop exploring move B's subtree entirely. ✂
```

On a 3×3 board this matters less (only 9! = 362,880 states), but on larger boards pruning dramatically reduces computation.

---

### 3.5 `best_ai_move(board)`

```python
def best_ai_move(board):
    best_score = -math.inf
    best_move  = None

    for move in get_available_moves(board):
        board[move] = "O"
        score = minimax(board, 0, False)   # Human moves next → minimizing
        board[move] = " "
        if score > best_score:
            best_score = score
            best_move  = move

    return best_move
```

This is the **entry point** for the AI's decision. It:
1. Tries every available cell
2. Calls `minimax()` to score the resulting board (assuming Human plays optimally from there)
3. Returns the index with the highest score

Note that `minimax(board, 0, False)` starts with `is_maximizing=False` because the AI just placed its mark — the **next** turn belongs to the Human (minimizing).

---

### 3.6 `play_game()` — Game Loop

```python
current_player = "X"    # Human always goes first

while True:
    print_board(board)

    if current_player == "X":
        move = get_human_move(board)
        board[move] = "X"
    else:
        move = best_ai_move(board)
        board[move] = "O"

    winner = check_winner(board)
    if winner:
        # announce result and break
        break

    current_player = "O" if current_player == "X" else "X"
```

Structure is nearly identical to the 2-player version. The only difference: instead of calling `get_player_move()` for both turns, one branch calls `best_ai_move()`.

| Concept | Where Used |
|---|---|
| **List comprehension** | `get_available_moves()` |
